# G3.10 — Runtime State & Recovery

G3.10 introduces a fail-closed runtime session state machine.

## State model

`CREATED -> ACTIVE -> DEGRADED -> RECOVERING -> SAFE -> CLOSED`

Faults move an active session to `DEGRADED`. Recovery is explicit and ends in
`SAFE`, never directly in an executable state. The kill switch remains engaged
throughout the lifecycle.

## Invariants

- recovery requires an explicit degraded state;
- empty fault reasons are rejected;
- closed is terminal;
- recovery cannot authorize runtime execution;
- the kill switch remains engaged;
- no external process, input, network control, or real NosTale execution is introduced.

## Exit criteria

CI, regression, safety and benchmark gates must pass before merge. Runtime
execution remains outside the scope of G3.10.
